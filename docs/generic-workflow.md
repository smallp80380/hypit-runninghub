# Native Workflow and AI App operations

One account Endpoint serves API-accessible RHCoins workflows and AI Apps without per-ID Model registration. Saved workflows and full API graphs retain their existing contract. Apps use their own `webappId` and fetched editable interface, never a workflow-ID alias. Backend availability and custom input semantics remain RunningHub responsibilities.

## Public contracts

`@local/provider-runninghub/generic` exports the public nominal `workflowManifest`, `workflowComponent`, `workflowFragment`, Capability/Type/Producer references, request/result validators and `createWorkflowProvider`. SDK imports use only public Distribution subpaths. This custom Module uses `ModuleManifest`, `TypeValidatorFacet`, `ProducerFacet` and `sealGraphFragment`; it does not use the exact-generation port/result shape.

Config `hypit-runninghub.config@2` is account-only: CredentialRef, official base origin, COINS_ONLY gate, shared `native-account` capacity/concurrency 1, filename upload and V2 query. Optional `accessPassword:{store,key}` is a second CredentialRef, never a literal or request field. One Endpoint selects one password; another password requires another Endpoint. Disabled examples grant no execution permission. Config @1 and descriptors/bindings @1/@2 retain their separate behavior.

`hypit-runninghub.request@1` contains explicit `workflowId`, optional `workflowJson` string, `nodeInfoList`, ordered `{key,blob}` files, `{fileKey,nodeId,fieldName}` bindings, optional `instanceType` and a private owner-review path. Native `workflow:string` overrides the still-required workflowId. All field values retain canonical JSON types, including arrays/objects/false/null/zero. New optional node inputs remain backend-validated. Duplicate targets are rejected. One file can bind multiple fields; there is no provider media-count cap. `instanceType` is exactly `default|plus|ultra` when present; absent stays absent and errors never switch tier.

Both capabilities return `hypit-runninghub.result@1` / nominal `WorkflowResult`: taskId, ordered BlobRefs, output types, safe metadata and reported usage. All query files are collected, including >20, image/audio/video/3D/text/JSON/binary files and unknown extensions; there are no synthesized inline text/JSON variants. Actual safe Content-Type is preserved; missing MIME becomes application/octet-stream. A download Content-Type containing a captured credential fails `UNSAFE_RESULT_MIME` before ResourceStore writes, rather than substituting another MIME. Empty SUCCESS returns an empty collection. Private bounded query observations retain noncredential evidence and signed URLs while redacting captured credential echoes. Public metadata strips secrets and HTTP(S) URLs from both property names and values, recursively. Downloads enforce origin/redirect/size limits and never send API/password credentials.

Reported usage is billing-validated before credential checks. Decimal strings containing either captured credential fail `CREDENTIAL_IN_RESULT_USAGE` before results persistence or collection, including legacy saved results; fixed usage field names and null absence sentinels remain structural. Money validation/latching is never replaced by redacted amount strings.

## AI App interface and authoring

`@local/provider-runninghub/ai-app` exposes App request/document/author/review/candidate helpers and nominal references. Pure Node subpaths `ai-app-document`, `ai-app-author-source`, and `ai-app-review-candidate` need no Hypit SDK loader. The same Module `@local/provider-runninghub@1` declares `AiAppRequest`, `AiAppDraft`, `run-ai-app`, `bind-ai-app-file`, and `finalize-ai-app`; result/file-key/output-index types and output selection remain shared.

Read-only `fetch-app` accepts a decimal string ID (1–40 digits) or official HTTPS `/ai-detail/<id>` URL. Workflow `fetch` also accepts `/post/<id>`. IDs never pass through JS Number. Kind mismatch, userinfo, explicit port, foreign origin or path are rejected before network IO. Page query/hash is ignored; no page is fetched and its origin never changes the configured account.

Metadata uses only `GET /api/webapp/apiCallDemo` with exact `apiKey`/`webappId` query plus Bearer auth. Its credential-bearing URL is never public. `curl` is neither executed nor persisted. The document stores ID/origin/name, boolean `accessEncrypted`, and ordered literal `nodeId,nodeName,fieldName,fieldValue,fieldData,fieldType,description,descriptionEn` strings. `appDigest` pins canonical official origin, ID, accessEncrypted and these nodes—not app name, counters or fetch time. Equivalent accepted origin spellings, including a trailing slash, produce the same document/digest; validation does not mutate caller data. Previously fetched snapshots whose digest included a noncanonical origin spelling require refetch and renewed owner review, not a legacy digest alias. Endpoint configuration and existing Workflow fingerprints are not globally rewritten.

`fieldData` is not a universal enum/schema: required/range/cardinality semantics are not inferred. `request-from-app` preserves every default fieldValue in metadata order. Overrides replace known targets in place; bound targets omit their defaults until upload supplies filenames. Unknown targets, duplicates and override+binding conflicts fail before effects. An empty interface is valid. Canonical App request format is `hypit-runninghub.ai-app-request@1`, with string webappId, nodeInfoList/files/bindings, optional review/instanceType; no graph, workflow ID or password literal.

```sh
rh-workflow fetch-app --config ./examples/ai-app-fetch.json --output ./app-document.json
rh-workflow inspect-app --input ./app-document.json
rh-workflow request-from-app --input ./app-document.json --values ./app-values.json --output ./app-request.json
rh-workflow author-from-request --input ./app-request.json --id app --files ./app-assets.json --outputs ./app-outputs.json --output ./app.svml
rh-workflow review-candidate --input ./app-request.json --config ./examples/generic-config.json --app ./app-document.json --credential-sha256 <actual-key-sha256> --files ./app-review-files.json --output ./app-candidate.json
```

These commands prepare new files, not paid tasks. Fetch reads only metadata through the explicit CredentialRef resolver; CLI supports the configured env store, while SDK consumers supply their own resolver. Supply values `{nodeInfoList,files,bindings,review,instanceType}` only; omit unused options. Asset files contain `{key,src,mediaType}`, selected outputs `{name,index}`, review files `{key,path,mediaType}`. For a configured password add `--access-password-sha256 <actual-password-sha256>`; actual secrets are never CLI flags. The candidate remains `UNREVIEWED_OWNER_MUST_CHECK`, with null dates, and must not be installed as approval.

Profile binds both `@local/provider-runninghub@1#run-workflow` and `@local/provider-runninghub@1#run-ai-app` to the same account Endpoint; `examples/ai-app-profile.json` is disabled. After separate owner review and explicit spending authorization, ordinary `hypit check`, `plan`, `doctor`, `pricing`, `build --follow`, `inspect` and `get` use `<AiApp>` like `<Workflow>`. `get` exports the composite value.json/resources; `<Output name="chosen" index="0"/>` selects a file. Pricing provides the Membership source page, not a fabricated numeric quote.


## Review and durable effects

`REVIEWED_WORKFLOW_OPERATION@1` pins the full workflow graph. `REVIEWED_AI_APP_OPERATION@1` instead pins appDigest and scope `reviewed-ai-app-only-no-external-money`, with human kind `project-owner-reviewed-membership-key-and-ai-app`. Neither record authorizes the other service. Both pin account/origin, CredentialRef and actual key hash, request values/tier, ordered file key/MIME/size and actual byte hashes, Membership source, reviewer and expiry. Ephemeral ResourceStore IDs and review paths are excluded from the semantic request digest.

If a password is configured, its ref/hash must be present in review and execution identity even for an unencrypted App. An encrypted App requires a resolved password before any upload/submit. It is injected only into the final applicable submit; unencrypted Apps do not receive it. Fixed protocol formats, official origins, service IDs, generated digests, SDK Blob resource identities and validated byte sizes are not treated as credential echoes. Resource contents still require normal admission before effects. Editable values and arbitrary retained metadata are checked using JSON primitive spellings, including numeric/boolean/null echoes; unrelated values retain their types. No minimum password length is imposed. Credential echoes in remote filenames, task IDs, MIME headers and download URLs still fail closed. Wrong passwords/tiers are terminal under existing error classification, with no monetary/tier fallback.

Start admission gates run before credential access. Required slots are captured once inside the guarded wrapper; unused password slots are not read. Getter/acquisition failures return sanitized failures without receipts until all required secrets were successfully captured, so an uncaptured password cannot escape through a task ID.

The App API reveals no hidden graph/version. Interface digest and owner review cannot guarantee hidden implementation stability. The owner must separately confirm the specific Membership key, App and chosen parameters incur no consumeMoney/third-party Money. If this cannot be confirmed, deny execution. NORMAL accountStatus and positive coins are consistency checks, not a Membership verifier.

One journal root uses account instance + Runtime operation across both service kinds. Changed request/key/password/kind cannot open another retry series. A structurally validated durable submit ACK resumes offline even when preparation/submit lock directories survive SIGKILL during checkpoint. Recovery revalidates preparation, source/body, upload bindings and captured identity, then only checkpoints/returns the saved handle: no locks are reclaimed, execution records rewritten, admission run or network effects repeated. Unknown/in-flight outcomes and malformed action histories remain fail-closed. Three TOTAL transient attempts remain durable for upload/submit. Every App submit re-fetches metadata after blocking account/file admission; changed appDigest returns `AI_APP_REVISION_MISMATCH` without another submit. Files are admitted again after this final GET. Shared preflight checks account age and the minimum initial/latest approval expiry with a fresh clock sample after the post-account private review read; the App final review read is checked again afterward. This is a client-side recheck, not an atomic server revision lock. All files are admitted before first upload and bytes rechecked at effects.

Query `CREATE` is pending; `CANCEL` is terminal `REMOTE_TASK_CANCELLED` with receipt. Positive Money usage fails before collection; a durable billing-violation latch also blocks older ready results after restart. Valid positive `consumeMoney` or `thirdPartyConsumeMoney` sets the latch independently of malformed sibling usage fields, whose schema errors remain failures. A compact denial record is persisted before redacting/storing full query evidence: redaction can expand the response beyond the journal budget. If full evidence storage fails, its error remains visible and the saved latch still denies collection/polling. Observed Money is terminal even when the HTTP response would otherwise permit a transient retry. Collection checks the latch before accessing saved results. Failure receipts and public errors never include source URLs, response bodies, key/password bytes or signed output URLs.

`maxRequestBytes` is <=4 MiB; journal budget is <=64 MiB and must cover request serialization and raw response envelope. Worst-case mapped filenames are checked before upload using the client's 4096-character durable-state limit (not an upstream promise). Private state is 0600 in 0700 directories. Container signature checks verify format prefixes, not full decoding, archive contents or backend custom node behavior. Documented upload families: PNG/JPEG/WEBP, MP3/WAV/FLAC, MP4/AVI/MOV/MKV and image ZIP archives, <=30 MiB per file. ZIP is never locally extracted.

App metadata fetch accepts integer timeouts 1–600000 ms and response budgets 1–16777216 bytes, including the Endpoint's 1–10485760-byte range. Budgets are not clamped: a valid budget smaller than the reply fails `RESPONSE_TOO_LARGE`. The separate legacy workflow-fetch configuration limits are unchanged.

## Gate status

Workflow/App preparation, Author input binding/projection, separate reviewed admission and shared durable execution are implemented. Behavioral suites exercise canonical source origins, interface/file drift during admission and final metadata GET, review expiry during asynchronous reads, ordered files, key/password binding and protocol collisions, primitive credential echoes, fresh-process SIGKILL ACK recovery, active-writer exclusion, malformed action histories, nested URL metadata sanitation, MIME/header protection, HTTP boundaries and Money refusal with malformed usage or overflowing evidence using injected mocks. The ordinary installed proof harness exercises the shipped CLI and Hypit Build/get without a development loader. These automated checks use no real API credentials or paid generation; they do not prove each real account App is available or verify backend generation quality/charges. Neither documentation nor disabled examples authorize execution.
